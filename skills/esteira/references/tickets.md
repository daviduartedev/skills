# Tickets

Load when the spec issue exists and the breakdown is not yet approved.

Draft tracer bullets from the spec. Each ticket:

- cuts a narrow path through the layers that ticket touches, and that path is complete
- is demoable or verifiable on its own
- fits in one fresh context
- names the tickets that block it, or states that none do

Show a numbered list: title, blocked by, what it delivers. Ask whether the size and the edges are right. Publish after the user approves.

Publish blockers first, one issue per ticket, so later tickets can name real identifiers. The parent is the spec issue. Use the same ready label as the spec. Body:

- **What to build.** User-visible behaviour.
- **Acceptance criteria.** Checkable facts.
- **Blocked by.** Identifiers, or none.

No file paths. Comment the ticket list on the spec issue. Leave the spec issue open.

When the consumer has no issue tracker, ask where the tickets should live before writing them.
